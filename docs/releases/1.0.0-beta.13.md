### Active Candidate Package — Windows Release Storage Isolation

To resolve a process-safety gap discovered during Gate-12 rendered Windows preflight (where launching normal Windows Release on the developer host risked reading/writing/mutating the real `%LOCALAPPDATA%\KnownFirst` profile), the candidate package on branch `fix/windows-release-storage-isolation-v1` implements narrow Windows Release storage isolation:
- When activated via canonical `KNOWNFIRST_GUI_TEST_ROOT`, redirects SQLite database (`knownfirst.db3`), preferences (`IsolatedFilePreferences`), merge safety copies, rolling application logs, and lexical diagnostic logs under `artifacts\gui-tests\windows\profiles\`.
- Replaces static `Preferences.Default.Clear()` in Settings full reset with injected `IPreferences.Clear()` to honor storage isolation.
- Omits the GUI test profile indicator banner and root path from DOM and accessibility trees in Release builds (`GuiTestProfile.ShowsProfileIndicator` evaluates to `false`).
- Retains normal production persistence when `KNOWNFIRST_GUI_TEST_ROOT` is unset.
- Excludes broader test seams (`GuiTestSeedLookupProvider`, `GuiTestFaultInjection`, etc.) from Release builds (`KNOWNFIRST_GUI_TEST_PROFILE_SUPPORTED` remains unchanged).
- Adds `scripts/gui-tests/windows/run-windows-release-visual-check.ps1` as a safe manual Release visual-check launcher with before/after real-database hash verification.
- **Focused TDD evidence:** genuine RED `18 passed / 6 failed / 0 skipped / 24 total` → GREEN `24 passed / 0 failed / 0 skipped / 24 total`.
- **Pre-commit review:** `0 BLOCKER / 0 MAJOR / 0 MINOR / 0 NIT`.
