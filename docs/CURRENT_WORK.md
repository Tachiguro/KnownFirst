It closes the residual Package D deliberately left open: the populated-target merge path's `LearningReview` plan-action lookup key and the Schema-9 meaning-aware review-event fingerprint. See [architecture/backup-merge-v1-design.md](architecture/backup-merge-v1-design.md) §22 for the full design record and [BACKLOG.md](BACKLOG.md) `KF-BACKUP-004` for the backlog entry.

- **`PLAN_ONLY`:** proved that the decisive defect was not only the fingerprint's field set but the writer's action-key collision. The planner labelled each `LearningReview` action `CardId@ReviewedAtUtc`, and `MergeWriterExecutor` indexes actions by that label with a last-wins assignment, so two physically distinct archive review rows for one card at one instant collapsed onto whichever action was recorded last — either dropping a genuinely new event or re-inserting a duplicate, while preview counts still reported both. Existing coverage proved the design's retention rule only in the pure `MergeFixtureSet.DeduplicatedUnion` helper, never through the real planner → writer path.
- **Architecture resolution (decided from binding repository evidence):** `LearningSessionId` and LearningSession stable identity are **intentionally excluded** from `LearningReview` merge identity — design §6 defines the immutable real-world event identity without it, the Schema-8 meaning-centric correction requires only the two answer-variant references to be incorporated, and Package D states that its archive-ordering material (which does include the mapped `LearningSessionId`) must never be reused as merge identity. Folding it in would couple event deduplication to workflow-session identity stability and risk duplicating historical reviews across installations. Stable `TargetAnswerVariant`/`MatchedAnswerVariant` identities **are** included. A review's session remains its referential workflow attachment and provenance.
- **`IMPLEMENT`:** nine focused tests added first.
