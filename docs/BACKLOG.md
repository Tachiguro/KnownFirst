# KnownFirst Internal Backlog

A compact, authoritative internal backlog for solo development and agent orchestration. GitHub Issues are deferred until collaboration or external testing makes them useful; this file is the durable single source of truth for accepted open work, product decisions, deferred follow-ups, and multi-package initiatives.

## Governance & Invariants

1. **Durable Tracking Requirement:** Every accepted bug, UX refinement, product decision, risk, follow-up, or required downstream package must have durable repository tracking in this backlog before unrelated implementation proceeds. Unfinished accepted work must never exist only in chat, prompt text, PR comments, or transient status notes.
2. **Backlog Authority:** `docs/BACKLOG.md` is the authoritative durable registry for all accepted open work outside active implementation branches. `docs/CURRENT_WORK.md` describes only the active package/branch; `docs/ROADMAP.md` sequences larger milestones; stable architectural decisions belong in ADRs or specifications linked from here.
3. **Identifier Immutability:** Existing stable `KF-*` IDs must never be renumbered or silently repurposed. New entries receive non-conflicting IDs matching the existing naming patterns.
4. **Follow-Up Closure Audit:** Every package-level `DOCUMENT_ONLY` phase must perform a Follow-Up Closure Audit: every intentionally deferred, excluded, newly discovered, or downstream accepted item must either link to an existing open `KF-*` ID or be added to this backlog before package reconciliation is complete.
5. **Foundation Milestone Rule:** Merging a foundation or sub-package (such as a core engine or domain model) must never cause its parent initiative or roadmap milestone to be marked complete while required downstream packages (persistence, archive, runtime cutover, UI) remain open.
6. **Again Queue Binding Invariant:** The implemented active-session Again/Nochmal behavior—every explicitly committed Again appends exactly one repeat to the tail of the active session queue; existing incomplete work remains ahead of that repeat; repeats may chain without an arbitrary cap; active-session repetition remains distinct from scheduler `DueAtUtc`—is an established binding regression invariant that must remain intact across the FSRS production cutover, not an open defect.
