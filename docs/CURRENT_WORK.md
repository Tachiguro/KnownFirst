## German Enhanced Term Recognition — Package 5A (Merged Production State)

Packages 1–4 (PR #134) and Package 5A (PR #135) are both merged production `master` state and are documented as stable capabilities in [docs/PROJECT_STATE.md](PROJECT_STATE.md). Package 5A — derived-term post-review lifecycle integrity — is merged to `master` at `683f34473dd21417be9d8e1b60d04de539fb35a8`. Full architectural framing: [docs/PROJECT_STATE.md](PROJECT_STATE.md) "German Enhanced Term Recognition — Package 5A (Merged Production State)."

- **Scope:** corrects the lifecycle of a derived compound component's `ReviewCandidateEntity`/`DerivedTermEvidenceEntity` around and after review completion, given that a derived candidate deliberately never receives a `WordOccurrenceEntity`. Touches `TextReviewService.CompleteSession`, `DocumentCleanupOperations`, `PreparationService`/`PreparationServiceSchema8`/`Schema8EvidenceScanner`, and the portable V2 backup mapper (`BackupModelMapperV2`, `Schema8BackupSnapshotRepository`, `Schema8BackupSnapshot`, `BackupSnapshotCapture`). No schema/version change, no archive-format change.
- **Unknown derived evidence retention:** when a derived candidate is decided `UnknownBacklog`, its owning `ReviewCandidateEntity` and `DerivedTermEvidenceEntity` row(s) now survive normal review-session completion, so Preparation can still recover a real source-compound context. Known/Ignored derived candidates and every Direct candidate continue to be cleaned up exactly as before.
- **Sentence/document dependency protection:** the `Document` and exact `SentenceSpan` a surviving evidence row depends on are now protected from generic maintenance cleanup (document/sentence-span sweeps reached from any unrelated review or preparation completion elsewhere in the app), scoped through the real candidate→session→document/sentence foreign-key relationships. Genuinely unreferenced documents/sentences with no retained evidence remain fully cleanup-eligible.
- **Preparation source-compound context fallback:** both the review-words display path and the Accept path now build context from the retained evidence's real whole-compound source span (never a fabricated component occurrence) when zero valid ordinary occurrence contexts remain, and agree with each other on when that fallback activates.
- **Cleanup on MarkKnown/Exclude:** when the retaining word leaves the Unknown lifecycle, its retained evidence and owning candidate are deleted at that point, scoped to exactly that word.
- **Portable V2 filter (superseded by Package 5A-2, see below):** on merged Package 5A, the portable/full-backup snapshot capture identified which captured `ReviewCandidates` own retained derivation evidence (Schema-11-only, internal enrichment, never itself exported) and the V2 mapper excluded exactly those specific candidate rows from exported review-workflow items, so a Completed session would not leak a provenance-less item. This exclusion is superseded on the local Package 5A-2 branch (not yet merged): the retained candidate is now exported through the ordinary completed-review-item path with its evidence transported alongside it — see "German Enhanced Term Recognition — Package 5A-2" below.
- **Evidence boundary:** the exact-head `FULL_VALIDATION` above proves only the automated scope the canonical launcher executed on the merged Package-5A candidate — 2227 automated tests, Windows Debug/Release builds, Android Debug/Release builds. It does not prove GUI/manual UX correctness, device/emulator runtime behavior, APK/AAB installation behavior, signing correctness, Google Play readiness/publication, or Package-5A-2 evidence beyond what is separately recorded below.
