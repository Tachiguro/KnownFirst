# German lexicon runtime asset — data provenance and license notice

This directory contains a single authoritative, compact, offline runtime
bundle (`german-lexicon.v2.kfgl`, format version 2) that is
**processed/derived from upstream German morphological dictionary data**.
It is not KnownFirst-authored linguistic data.

The bundle carries its lexical index together with its own machine-readable
provenance (upstream project/repository/commit, source path, source
SHA-256, data-license identifier, and generation counts) in one file,
closed under one trailing SHA-256 checksum over the whole bundle. There is
no separate generated manifest file: provenance for the currently accepted
bundle is read directly from the bundle itself (e.g.
`GeneratedGermanLexicon.Provenance` / `.Counts`), which guarantees lexical
data and its provenance can never be out of sync with each other.

## Upstream source

- Project: `german-morph-dictionaries`
- Repository: <https://github.com/DuyguA/german-morph-dictionaries>
- Pinned commit: `1780890c0fd25a989201c96000af323cd201fa5c`

- Source archive SHA-256: recorded inside `german-lexicon.v2.kfgl`'s

## Data license

The upstream data is **CC BY-SA 4.0** (Creative Commons
Attribution-ShareAlike 4.0 International). At the pinned commit above, the
upstream repository's `LICENSE` file is the CC BY-SA 4.0 legal text, not
MIT — an older MIT reference in the upstream `README.md` at that point in
its history does not govern the data and must not be treated as the
license. A verbatim copy of the upstream `LICENSE` file at the pinned
commit is kept alongside this notice as `UPSTREAM_LICENSE.txt`.

This CC BY-SA 4.0 designation applies to the upstream **data** consumed to
produce `german-lexicon.v2.kfgl`, and to the generated runtime index itself
as a derived work of that data. It does not apply to KnownFirst source
code, which remains Apache-2.0 (see the repository root `LICENSE`).

## What the generated bundle contains

`german-lexicon.v2.kfgl` is a compact binary bundle of:

- machine-readable provenance (upstream project/repository/commit, source
  path, source SHA-256, CC BY-SA 4.0 license identifier, provenance
  statement) and generation counts, followed by
- unambiguous German base-form lemmas (nouns, verb infinitives, adjectives)
  confirmed by the upstream morphological analyses, and
- a small set of compound-initial verb stems derived from the upstream
  verb imperative-singular (`V,imp,sing`) analyses (see the parser/builder
  documentation in `scripts/tools/GermanLexiconGenerator/` for why this,
  rather than a literal upstream "TRUNC" tag, is the genuine evidence used
  for compound-stem recognition; this evidence is useful for many verbs
  but does not give complete coverage for strong/irregular German verbs),

closed under one trailing SHA-256 checksum over the entire bundle.

It contains **no** definitions, translations, example sentences, provider
state, user vocabulary, or online-lookup data of any kind.

## Format and generation

- Generated bundle format/version 2 (see `GermanLexiconRuntimeAssetFormat`
  in `KnownFirst.Core/Text/German/`). Provenance and generation counts are
  read directly from the bundle at load time
  (`GeneratedGermanLexicon.Provenance` / `.Counts`) rather than from a
  separate manifest file.
- The bundle is generated by the Apache-2.0 KnownFirst maintenance tool at
  `scripts/tools/GermanLexiconGenerator/`, which fetches only an explicitly
  pinned upstream commit (never branch "latest") and regenerates this
  bundle deterministically — identical input bytes reproduce identical
  output bytes. Publication replaces the single authoritative bundle file
  via one same-directory replacement operation, after the newly staged
  bundle has been fully reopened, validated, and confirmed to match the
  intended provenance and counts; a failed or interrupted generation never
  disturbs the previously accepted bundle. This is a single replacement
  operation rather than a sequence of independent writes; it does not
  promise universal crash/power-loss atomicity, and recovery from an
  unlikely OS/filesystem-level interruption is simply re-running
  generation from the pinned upstream commit.
